# Модуль валидации

## Структуры данных

### Правило валидации
```
{
  property?: "type" | "length";
  condition: "=" | "!=" | ">" | "<" | ">=" | "<=" | "in" | "not-in" | "null" | "not_null";
  value?: any;
  message?: string;
}
```

### Массив правил валидации

Массив может содержать только правила валидации или только массивы.
Правила внутри одного массива обрабатываются через И
Правила в двух сосдених массива обрабатываются через ИЛИ
Например:
```
[ a, b, c] -> a И b И c
[ [a, b], [c]] -> (a И b) ИЛИ c
[ [a, b], [[с], [d, e]]] -> (a И b) ИЛИ (c ИЛИ (d И e))
```

### Проверяемое значение

Переменная любого типа

## API модуля

### Проверка одного значения

На вход получает значение любого типа и массив правил валидации.
Создается инстанс ValidationErrorMessage.
Значение проверяется на соответствие каждому правилу.
При несоответствии добавляется ошибка в ValidationErrorMessage (поле message у правила если есть, иначе все правило). Дальнейшая проверка не производится.
На выходе возвращается итоговая строка из ValidationErrorMessage.

### Проверка множества значения

На вход получает два обьекта:
- Record<string, any> значения
- Record<string, Правило валидации[]> правила проверки

Создается общий инстанс ValidationErrorMessage для всех и отдельные инстансы на проверку каждого свойства. Для каждого свойства обьекта значения вызывает валидацию используя соответствующий список правил валидации. Если для свойства нет соответствующего списка правил, оно пропускается.

Результат проверки каждого свойства складывается в общий инстанс ValidationErrorMessage. 
На выходе возвращается итоговая строка из ValidationErrorMessage.

## Обработка правил

Отсутствие значения (типа undefined) считаем как null. isNull(undefined) === true;

Если property = "type" проверяет тип переменной
Тогда condition: "=" | "!=" | "in" | "not-in"
Тогда value: ожидаемый тип переменной

Если property = "length" проверяет длину значения (актуально только для строк и массивов)
Тогда value: число или массив чисел

Если condition = "null" | "not_null"
Тогда value не имеет значения. Отсутствие значения (типа undefined) считаем тоже null.

Если value regExp
Тогда condition: "=" | "!="
Значение string или number, иначе ошибка.
Тип number приводится к string, далее проверяется на соответствие regExp
Для "=" regExp должно что-либо найти, для "!=" наоборот
